## [Unreleased]

Target: **1.27.0** (minor). REQ-ARCH-001 rules 2, 6 and 8: the bundle works on its own entity manager; XML mapping;
standard-host and DDD-host kernel tests. No schema or data change. See [UPGRADING](UPGRADING.md#to-1270).

### Changed

- **Rule 6:** every bundle service and the bundle's internal repositories read and write through a private entity
  manager (`Doctrine\UptimeEntityManager`) created on the connection of the manager that maps the bundle entities, with
  that manager's mapping configuration and event manager. A bundle write flushes only bundle rows; an application
  manager is never flushed, cleared, closed or reset by the bundle (`TenantProvisioner` used to flush the host default
  manager, with whatever the host had pending). A failed bundle flush closes only the private manager, which the next
  call replaces. `ClosedEntityManagerSubscriber` and the failed-import recovery reset only that manager.
- `TenantProvisionerInterface::ensure()` returns the tenant of the application manager that maps the bundle entities;
  `CheckExecutorService::execute()` and `MonitorBackupService::import()` accept an entity of that manager and work on
  the bundle copy. The repository services by class name stay on the application registry (unchanged).
- After the incident listeners, the application manager is flushed only with `doctrine.flush_listener_changes` and
  only when nothing was pending there before the listeners (BC, with a deprecation).
- `nowo:uptime:sync-schema` targets the bundle's connection.

### Added

- `doctrine.connection` (rule 8, validated at build time), `doctrine.register_mapping`, `doctrine.mapping_type`
  (`attribute` | `xml`) and `doctrine.flush_listener_changes`.
- XML mapping of the six entities in `src/Resources/config/doctrine/*.orm.xml` (same tables, columns, indexes,
  constraints and PHP types as the attributes; a parity test compares the metadata and the schema).
- `EventSubscriber\WorkerBoundaryResetListener` (REQ-RUNTIME-002): drops the private manager at the main request,
  `kernel.terminate`, Messenger received / handled / failed and console command / terminate; the manager is also tagged
  `kernel.reset`.
- Kernel tests for a standard host (zero config, 1,000 kept-alive requests alternating two tenants with rows changed by
  another process, memory bound, every boundary) and a DDD host (XML-only mapping, bundle on a dedicated manager and
  connection); a DB test proving that host pending changes are untouched, host transactions include the bundle rows
  and a failed bundle flush loses no committed row.

### Deprecated

- The root `connection` key: use `doctrine.connection` (removed in 2.0).
- `doctrine.flush_listener_changes: true` (the 1.x default): 2.0 never flushes an application manager.

### Fixed

- `specs/001-baseline/code-inventory.md` lacked `EntityManagerOptionPass` (1.26.0).

## [1.26.0] - 2026-11-11

Closed-manager recovery and backup import reset only Uptime's own entity manager, never a host one; new validated doctrine.entity_manager option. See [UPGRADING](https://github.com/nowo-tech/UptimeMonitorBundle/blob/v1.26.0/docs/UPGRADING.md#to-1260).


### Fixed

- `ClosedEntityManagerSubscriber` reset **every** closed entity manager of the registry before a bundle route, host
  managers included, and `MonitorBackupService::import()` did the same after a failed import flush. Both now reset only
  the bundle's managers: the manager of the bundle entities (`getManagerForClass(Monitor)`, always included) and, for
  the import, the manager it wrote through. Rule 6 of the bundle architecture bar; standard hosts with one default
  manager see no change.

### Added

- `nowo_uptime_monitor.doctrine.entity_manager` (default `null`): an additional entity manager that maps the bundle
  entities (the host maps them there itself), reset by the bundle too. It only adds to the manager above (audit
  LD-UM-M1). The build fails when the manager does not exist or does not map `Nowo\UptimeMonitorBundle\Entity`. The
  bundle mapping and writes stay on the default manager; a dedicated manager is not supported yet.

## [1.25.2] - 2026-11-10

Target **1.25.2** (patch, security).

### Security

- **A mask with nothing stored behind it is never saved or sent as `***` (KE-U151-L1).** In 1.25.1 a mask that had no
  stored value to put back was stored and sent literally: a renamed header (`X-Other: ***`), a new or surplus
  credential-like parameter (`tokenx=***`, a third `token=***`), a masked userinfo typed into a new monitor, and, with
  `form.hidden_fields: [httpHeaders]` and a URL moved to another host, every hidden header (`Name: ***`). The monitor
  form (new and edit) now refuses such a value on its field with "type the value or remove it"
  (`form.monitor.secret_mask_unresolved`, 422 in the dialog) and saves nothing. Where it cannot be typed (a field
  hidden with `form.hidden_fields`, a backup import, a host that calls `MonitorFactory::applyFormData()` itself) the
  header, the query parameter or the userinfo is dropped instead (`SecretRedactor::stripMaskedUrl()`,
  `stripMaskedHeaders()`). New `MonitorFactory::unresolvedMasks()`.
- **The request body is write-only in the monitor form (KE-U151-L2).** The edit form rendered the stored `httpBody`
  (for example a login JSON of a keyword check), although exports already blank it. A stored body is shown as `***`
  now: leave it (or blank) to keep it, type a new body to replace it, or tick "Remove the stored body"
  (`httpBodyClear`) to delete it. Like the other secrets it is only kept for the same scheme, host and port: when the
  URL's changed the form asks for it again (`form.monitor.secret_retype`), and a hidden body is dropped.
  `MonitorUpdatedEvent` reports `httpBody` by name only, comparing the stored body. Tenant managers only; no GHSA.
- **More credential-like query names are masked (KE-U151-I1):** `jwt`, `bearer` and `hash` join `token`, `key`,
  `secret`, `pass`, `pwd`, `sig` (also `signature`), `auth`, `credential`, `session` and `code` in the dashboard, the
  monitor page, alerts, webhooks, backups and the edit form. Masking stays name-based: a secret in the URL path (a
  Slack webhook `/services/T…/B…/…`, a Telegram `/bot<token>/`) or under another parameter name is not masked
  (documented in SECURITY.md and USAGE.md).

### Added

- `SecretRedactor::stripMaskedUrl()`, `SecretRedactor::stripMaskedHeaders()`, `MonitorFactory::unresolvedMasks()`,
  `MonitorFormData::$httpBodyClear` and the `httpBodyClear` form field.

## [1.25.1] - 2026-11-10

Target **1.25.1** (patch, security).

### Security

- **Monitor form: URL / proxy credentials and header values are write-only (KE-U-I5).** The edit form rendered the
  stored URL userinfo (`https://user:pass@host`), the stored values of credential-like query parameters (`?token=`,
  `api_key=`…), the proxy URL with its userinfo, and every custom header value (`Authorization`, `X-Api-Key`,
  cookies…) back to the browser (page, dialog and re-render after an error). They are shown masked now, with the same
  rules as the monitor page and backups (`SecretRedactor`): `https://***@host/path?token=***`, `Name: ***`. A
  submitted value that still holds the mask keeps the stored one (headers matched by name, case-insensitive); a typed
  value replaces it; removing the userinfo, the parameter or the header line removes it. `MonitorUpdatedEvent` reports
  `url`, `proxy` and `httpHeaders` by name only, comparing the stored values. Pre-existing, limited to users who may
  manage the tenant; no GHSA.
- **Stored secrets are not carried to another destination.** A mask is only put back for the same scheme, host and port
  (default ports filled in). When the URL's changed, the masked URL userinfo / token values, the masked header values
  and the blank basic-auth password (the 1.25.0 "keep" rule) are refused with "type this secret again or remove it"
  on their field (`form.monitor.secret_retype`) and nothing is saved; the same for the proxy's userinfo / token values
  when the proxy's changed. A field hidden with `form.hidden_fields` cannot be retyped: that secret is dropped. A
  backup import in overwrite mode refuses such a row (counted as invalid). New
  `MonitorFactory::secretsNeedingRetype()`; `applyFormData()` never restores a secret across destinations.
- Backups and the monitor page also mask the userinfo of a proxy written without a scheme (`user:pass@proxy:3128`).

### Added

- `SecretRedactor::maskEditableUrl()`, `restoreEditableUrl()`, `maskEditableHeaders()`, `restoreEditableHeaders()`,
  `sameOrigin()`; `MonitorFactory::secretsNeedingRetype()`.

## [1.25.0] - 2026-11-10

Target **1.25.0** (minor, additive; one documented event timing change).

### Added

- `StatusTransitionService::handleAfterCheckDeferred()` / `dispatchCommitted()`.

### Security

- **Monitor form: the basic-auth password is write-only.** The edit form rendered the stored password back to the
  browser (`always_empty: false`, prefilled by `MonitorFactory::toFormData()`). It is never rendered now: blank keeps
  the stored password, a typed one replaces it, and the new `authPasswordClear` checkbox removes it. Limited to users
  who may manage the tenant; no GHSA.

### Changed

- **Incident events after the commit**: `CheckExecutorService` dispatches `MonitorWentDownEvent` /
  `MonitorRecoveredEvent` after the check's flush instead of before it. The new incident's id is set; a failed flush
  dispatches nothing. What a listener persists is flushed right after the dispatch. A listener that throws is logged
  (class only) and the dashboard sync and parent group refresh still run (`StatusTransitionService` takes an optional
  logger, last argument). Same event classes and payload.
  `StatusTransitionService::handleAfterCheck()` (when called directly) keeps dispatching immediately.

### Documentation

- USAGE: new section "Using it from a DDD / hexagonal application" (where the bundle sits in a hexagonal host, the ports, events and DTOs to build an anti-corruption layer on, and the known limitations).

## [1.23.0] - 2026-11-08

### Added

- **404 for a refused tenant (UM-7):** `security.denied_tenant_status: 403|404` (default `403`, today's answer). With
  `404` and a tenant-aware access checker, a refusal on any `{tenantSlug}` route (admin pages, summary, settings, the
  status / history / aggregates APIs, every mutation) answers 404 when `canAccessTenant()` is false for that user and
  tenant, so a stranger or a user who may only read shared monitors learns nothing about the tenant (Beacon spec 174
  FR-005). A tenant member refused one action (edit, settings) keeps 403. Monitor reads under a monitor-aware checker
  are unchanged: a shared monitor stays readable, any other answers 404 as since 1.21. Without a tenant-aware checker
  or without a tenant in the URL nothing changes. The 404 is the answer of a missing tenant: `{"error":"Tenant not found"}`
  (`application/json`) on the APIs, `Tenant "<slug>" not found.` on the pages, so a refused tenant and a missing one
  cannot be told apart, provided `canAccessTenant()` is false for unknown slugs too. The setting changes the status
  code, not who gets in: see UPGRADING before deleting a host listener. Audit: Appendix IQ Pass-Low; IQ-L1, IQ-L2,
  IQ-I3, IQ-I4 addressed, re-verification pending.

## [1.21.0] - 2026-11-06

Host hooks so an embedding app can drop its listeners and its monitor page override (1.21.0, minor). Every option is
off by default: the default output does not change. See [UPGRADING](UPGRADING.md#to-1210).

### Added

- **Monitor page regions** (`web_ui.monitor_show`): `charts: bundle|host|none` (default `bundle`) and
  `slots.{figures,charts,details}` — templates rendered with the page variables in place of the key figures, the
  charts (with `charts: host`) or the details card. The regions are also the blocks `monitor_details`,
  `monitor_figures` and `monitor_charts`. `uptime-monitor-detail.js` already skips missing chart canvases.
- **Cancellable quota check** `Event\UptimeEvents::MONITOR_QUOTA_CHECK` (`Event\MonitorQuotaCheckEvent`: `action`
  `create|resume`, `tenantSlug`, `type`, `monitor`, `previousType`, `deny($reason)`), dispatched inside the tenant row
  lock before a new monitor is saved, a monitor changes type or a paused monitor is resumed, from the forms, the pause
  action and backup import. A denial shows the reason in the monitor form (dialog: 422), as an `error` flash or as an
  import warning (`quota_denied`, `quota_denied_reason` in the `import()` result); nothing is written for it.
  `limits.provider` stays. See [CONFIGURATION](CONFIGURATION.md#host-quota-check).
- **Tenant provisioner** `multi_tenant.provisioner` (`Tenant\MissingTenantProvisionerInterface`): creates the tenant
  of a slug without one when an admin page or tenant API runs, after the access check; null → 404.
- **Monitor-level read access** `Security\MonitorAwareUptimeMonitorAccessCheckerInterface::canViewMonitor()`: decides
  the monitor page and its history / aggregates APIs (404 when refused); tenant-wide pages and mutations keep the
  tenant methods. Default (other checkers): tenant access, as before.
- **Settings per tenant** `web_ui.settings.sections_resolver` (`Ui\SettingsSectionsResolverInterface`): narrows
  `web_ui.settings.sections` per tenant; a tenant without a screen has no Settings action or area tab.
- **`web_ui.strict_tenant_paths`** (default `false`): on the admin routes, a tenant is served only under the path its
  slug selects (`tenant_paths` entry or the default path); any other path answers 404. The status page and the tenant
  APIs are not covered.
- **`monitor_safe`** page variable of the monitor page (`target`, `config`, masked with `SecretRedactor`), for slot
  templates: `monitor` stays the raw entity.

### Changed

- The dashboard *Settings* action and the area *Settings* tab are left out when the tenant keeps no settings screen
  (before, they led to a 404). With the default `web_ui.settings.sections` nothing changes.
- A resume and a group created from the monitor form now run in a short transaction holding the tenant row lock. The
  responses do not change.

### Security

Findings of the independent review of this release's host hooks (REQ-SEC-004 Appendix GU), all before any release. Every
one needs a host to opt in to a hook; default configuration is not affected.

- **The host quota event could be avoided (GU-M1, Medium).** Editing a monitor (unchecking `paused`, a group into a
  check, `https` into `push`) and backup import never dispatched `MONITOR_QUOTA_CHECK`. They do now, including a backup
  overwrite, and a denied import row is reported instead of written. **Hosts with a pre-1.21 listener on `new` and
  `toggle_pause` only have the same gap in their listener: move it to this event.**
- **The resume check ran outside any lock (GU-L1, Low):** concurrent resumes could each pass a counting listener. It now
  runs through `TenantQuota::withTenantLock()`, as do edits with a check and group creation.
- **`canViewMonitor` did not narrow the monitor page (GU-L2, Low):** a user shared one monitor also got the names and
  statuses of unshared children of a shared group, the parent group's name and the push ingest URL. Children are filtered
  by `canViewMonitor()`; the parent and the URL need `canAccessTenant()`.
- **The provisioner got an unvalidated slug and ran before CSRF (GU-L3, Low):** a slug outside `SLUG_PATTERN` answers 404
  before it, and a POST never provisions.
- `TenantFormType::SLUG_PATTERN` no longer accepts a trailing newline (`$` without the `D` modifier), found while fixing
  GU-L3. It reached `TenantProvisioner::ensure()` through the API routes, which have no slug requirement.

## [1.20.1] - 2026-11-06

Dialog rule v2: the monitor dialog footer shows Cancel on every step; CI checks committed assets against the build.

Dialog rule v2 (owner decision D-20261105-54) for the monitor dialog (*New monitor* / *Edit monitor*). No configuration
change. See [UPGRADING](UPGRADING.md#to-1210).

### Changed

- **The monitor dialog's footer is filled on every step.** The form's actions row (Cancel, then **Save**, the one
  primary) still moves into the UiKit dialog footer, bound with `form="uptime-monitor-form"` (1.19); the steps without
  a form — loading, a load error, a file-managed monitor refused with 409 — now show **Cancel** (secondary) in the
  footer instead of an empty, hidden footer, from a `<template data-monitor-form-footer-idle>` in
  `monitor/_monitor_edit_modal.html.twig`. New monitor and Edit monitor share the same anatomy: header (title + ×),

- **Focus survives the footer swap** (audit GJ-I2): when the keyboard focus is on a footer control that a step change

## [1.18.0] - 2026-11-05

Monitors as code (`nowo:uptime:apply-monitors`) and a clearer monitor form. Schema change: two columns on
`uptime_monitor`. See [UPGRADING](UPGRADING.md#to-1180).

### Added

- **`nowo:uptime:apply-monitors --file=<json> [--token-file=<path>|-] [--tenant=<uuid>] [--dry-run] [--prune]`**:
  creates, updates or leaves unchanged the push monitors of a monitors file (schema
  `Resources/schema/apply-monitors.v1.json`), matched by a stable entry `key`. It is idempotent and all or nothing:
  one transaction under the tenant row locks, and any refusal applies nothing. stdout is one JSON document
  (`created` / `updated` / `unchanged` / `pruned` / `prune_candidates` / `warnings`, or `errors` as JSON pointer +
  code); the exit codes are 0 ok, 1 failure (rolled back), 2 usage, 3 invalid file, 4 token input refused, 5 tenant
  not found, 6 conflict or tenant limit. A `MonitorsAppliedEvent` listener that throws after the commit is reported
  as an `event_listener_failed` warning (exit 0, the run is applied) and the later tenants still get their event. Tenants are looked up by slug and never created. Only push monitors in this version.
- **External push tokens**: only through `--token-file` (a regular, non-symlink file of mode 0600/0400 owned by the
  process user or root, at most 64 KiB) or `--token-file=-` (a non-interactive stdin read to EOF; a terminal is
  refused), as a JSON map `{"<entry key>": "<token>"}`. Tokens must be 64–128 lowercase hex characters
  (`openssl rand -hex 32`) and pass minimum-entropy checks; each is reduced to its SHA-256 at once. A token whose hash
  differs from the stored one rotates it; the same token changes nothing. There is no token option on the command
  line, and no token, hash or token file path reaches the output, logs, events or exception messages (an error path
  names an entry key only when the monitors file has it, otherwise `token-file:/?`). The monitors file is read with a
  hard 1 MiB cap.
- **`--prune`** deletes the file-managed monitors of the listed tenants that the file no longer names (a tenant
  listed with `"monitors": []` loses all of them); without it they are reported as `prune_candidates`. Monitors made
  in the UI, by a backup import or by host code are never updated or pruned.
- **`MonitorsAppliedEvent`** (one per tenant, after the commit): entry keys, ids, changed field names and token
  states, for host audit logs.
- **`uptime_monitor.origin`** (`ui` / `file`) and **`origin_key`**, with a unique index on `(tenant_id, origin_key)`;
  `Monitor::getOrigin()`, `getOriginKey()`, `isFileManaged()`, `markFileManaged()`;
  `PushCredentials::hashToken()`.
- **File-managed monitors in the UI**: a "Managed from file (key)" badge in the monitor page header (new Twig block
  `monitor_origin_badge`), a "Managed from file (key)" detail and a short *File* badge on the dashboard rows; edit,
  delete and the push token actions are not offered and answer **409** when called anyway (the monitor dialog shows
  the server's message); pause / resume stays available.
- **Errors of every class in one run**: an invalid monitors file and a refused token input are reported together, as
  are a missing tenant and the conflicts of the tenants that exist; the exit code is the lowest class. An unknown
  option (such as `--token`) or an argument is a usage error (exit 2) in the same JSON shape.
- **Monitor form**: a one-line intro per section; units as a translated suffix (`form.monitor.unit.seconds`,
  `s` in the 7 shipped locales, hidden from screen readers) next to the interval, retry interval, timeout and grace
  inputs (no longer in the labels); help on name, interval, retry interval, timeout (it explains the
  48 s default: Uptime Kuma's 80 % of a 60 s interval, capped by `checks.max_timeout_seconds`), URL, method, keyword,
  max redirects and paused; placeholders for the text fields; switches (`role="switch"`) for paused, ignore TLS,
  upside down, certificate expiry and signed pushes; required markers on the target fields (hidden from screen
  readers: the inputs carry `required`). The server renders the selected type's sections with `hidden`, so the form
  reads right before (or without) the dialog script, and a field the browser refuses inside the folded *Advanced*
  block opens it.

### Changed

- **Monitor form layout**: *Paused* moved to General; keyword, max redirects, the TLS / upside-down / certificate
  switches, body, headers, authentication, proxy and tags are folded in one *Advanced* `<details>` block, open when
  one of them has an error or a non-default value. Push monitors no longer show the retry interval and timeout, ping no
  longer shows the port, DNS no longer shows the timeout. A section whose fields are all in `form.hidden_fields` is not
  rendered. New section keys `check-retry`, `check-timeout`, `tcp-port`; `http-options` is merged into
  `http-advanced` (the dialog script still understands it).
- **Backup export** rows carry `origin` and `origin_key` (informational); a backup import in `overwrite` mode skips
  file-managed monitors (counted as `skipped`).

### Fixed

- **An HTTP monitor without a URL, a TCP / ping / SSL monitor without a host (or TCP / SSL without a port) and a DNS
  monitor without a hostname were saved** and then failed every check. The form now refuses them on the field
  (`form.monitor.url_required`, `host_required`, `port_required`, `hostname_required`), and the dialog marks those

## [1.16.1] - 2026-10-29

`nowo:uptime:sync-schema` no longer drops host tables. See [UPGRADING](UPGRADING.md#to-1161).

### Security

- **`nowo:uptime:sync-schema` could drop host tables.** `SchemaSyncService::getUpdateSchemaSql()` called Doctrine's
  `SchemaTool::getUpdateSchemaSql()` with the bundle entities only. With Doctrine ORM 3 (no "save mode") that method
  compares the whole database with those entities, so the update SQL held `DROP TABLE` for every table that is not a
  bundle table (and `DROP SEQUENCE` for every sequence on PostgreSQL), and the command executed it — unless the host
  had configured a Doctrine `schema_filter` that hides its own tables. Every release up to 1.16.0 is affected when run
  on Doctrine ORM 3 (CWE-1188).

### Fixed

- `SchemaSyncService::getUpdateSchemaSql()` now builds the target schema from the bundle metadata
  (`SchemaTool::getSchemaFromMetadata()`), the source schema from only the bundle tables and sequences that already
  exist (`introspectTable()`), and returns the platform's `getAlterSchemaSQL()` of that diff: it can create, alter or
  index bundle tables, never touch another table or sequence. Covered by
  `SchemaSyncServiceDbTest::testSyncSchemaSqlNeverTouchesHostTables` on SQLite, MySQL and PostgreSQL.

### Security

SEC-004 re-audit 2026-10-27 findings (M1, L1–L7 and Info items):

- **One monitor can no longer stall or exhaust the shared scan (M1)**: new `checks.max_timeout_seconds` (60),
  `checks.max_body_bytes` (1 MiB), `checks.max_redirects` (20) and `checks.max_scan_seconds` (300; 0 = no budget) caps

  monitor form refuses timeouts above the cap.
- **Unstorable check data no longer stops the scan (N1)**: check messages and metadata are scrubbed to valid, bounded
  UTF-8 (`CheckResultDto::sanitized()`, e.g. a DNS TXT record with invalid bytes); when a flush still closes the entity
  manager, `DueChecksRunner` resets it through the registry, reschedules the failing monitor with a DQL update and
  reloads the remaining monitors.
- **Redaction (N2)**: URL userinfo is masked up to the last `@` of the authority, credential-like query parameter
  values (`token`, `key`, `secret`, `sig`, …) are masked, and backup exports drop the request body.
- **Disabled admin UI (N3)**: `web_ui.enabled: false` no longer registers the admin / mutation routes, and the access
  subscriber answers 404 for those controllers if a host imports `routes.yaml` directly.

- **Disabled tenants (L2)**: their monitors are no longer checked and their status page answers 404.

- **Monitor proxies (L4)**: with `block_private_urls`, the proxy host is resolved once, validated and pinned to that IP.

- **Backups (L7)**: exports redact secrets (URL / proxy credentials, basic-auth password, custom header values);

## [1.6.1] - 2026-10-13

### Security

- **SSRF / DNS:** DNS monitors now honour `checks.block_private_urls` (default `true`), like HTTP/TCP/SSL/ping. ## [1.4.0] - 2026-10-13

### Security

## [1.0.0] - 2026-07-06

First stable release of `nowo-tech/uptime-monitor-bundle`.

### Added

- Synthetic check runners: HTTP/HTTPS, TCP, DNS, SSL certificate, and Ping (ICMP).
- Symfony Scheduler integration and `nowo:uptime:run-due-checks` command.
- Doctrine persistence: tenants, monitors, check results, perpetual aggregates, and incidents.
- YAML retention (`detail_days`) with optional purge; aggregates kept forever (`nowo:uptime:rollup`, `nowo:uptime:purge-detail`).
- Multi-tenant dashboard at `/uptime/{tenantSlug}` with CRUD for monitors and tenants.
- REST summary API (`GET /api/uptime/{tenantSlug}/summary`) with `?since=` delta polling.
- Vite + TypeScript dashboard assets and Chart.js charts.
- Public read-only status page per tenant (`/status/{tenantSlug}`).
- Notifications on status change: email, webhook, and Slack (with cooldown).
- Uptime Kuma–style tenant **Settings** UI (`/uptime/{tenantSlug}/settings`).
- Mercure real-time dashboard sync (`dashboard.sync: mercure`, optional `symfony/mercure-bundle`).
- UI framework options: Tabler (default), Bootstrap, Tailwind, or custom host theme.
- SSRF mitigation for HTTP monitor targets (`MonitorUrlSsrfGuard`).
- Console commands: `nowo:uptime:sync-schema`, `nowo:uptime:seed-demo`, `nowo:uptime:clear-data`.
- Symfony Flex recipe (`.symfony/recipe/nowo-tech/uptime-monitor-bundle/1.0.0/`).
- Translations for UI and validators (`en`, `es`).
- Demo applications under `demo/symfony7` and `demo/symfony8` (FrankenPHP).
- Makefile targets for QA (`release-check`, tests, coverage, PHPStan, Rector) and `update-deps` (REQ-MAKE-008).
- Documentation: Installation, Configuration, Usage, Scheduling, Check types, Monitor configuration, Settings, Notifications, Mercure, Security, Contributing, Release, Engram, and spec-driven development.

### Requirements

- PHP `>=8.2 <8.6`
- Symfony components `^7.4 || ^8.0`
- Doctrine ORM/DBAL (see `composer.json`)
